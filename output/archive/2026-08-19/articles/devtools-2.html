GitHub Copilot CLIのworktree対応がv1.0.78で有効化、マルチ作業ブランチ前提のエージェント運用が前進

3行でわかる！今日のニュース
  • GitHub Copilot CLIがv1.0.78でworktree運用に前進する。
  • 複数ブランチをまたぐ作業が、より扱いやすくなる。
  • 周辺ツールも改善し、agent開発の流れが整う。

GitHub Copilot CLIはv1.0.78でworktree前提の運用に一歩近づき、複数ブランチをまたぐAIエージェント作業を扱いやすくしました。周辺ツールでもworktree切り替えの改善が進み、エージェント型開発の実装・検証フローが整いつつあります。

GitHub Copilot CLI moved closer to worktree-first operation in v1.0.78, making multi-branch AI agent workflows easier. Nearby tools are also improving worktree switching, suggesting a more practical setup for agentic development.

GitHub Copilot CLIのv1.0.78は、単なる機能追加というより、AIエージェントを“どのブランチで、どう安全に動かすか”という実運用の前提を一段押し上げる更新だ。今回の検索結果から確認できるのは、Copilot CLI側でworktreeを前提にした扱いが進み、関連する周辺ツールでも作業ブランチの切り替えが改善されている点である[3][1]。

まずCopilot CLIのリリースでは、エージェント向けの拡張機構として「Agent Plugins spec」に対応し、`com.github.copilot/extensions/` 配下で拡張を配布できるようになった。さらに `--plan` と `--mode autopilot` を組み合わせて、承認待ちを挟まずに計画から実装へ進める流れも追加されている[3]。これは、探索・計画・実装の切り替えをCLI上でより明確に扱えるようにする動きと見られる。

加えて、別の検索結果では、Copilot CLIに関する解説テーマとして「worktree対応」が取り上げられており、同じ文脈でClaude CodeのAuto ModeやCursorのルーター機能も並んで言及されている[2]。これらの周辺トピックが示すのは、AIコーディング支援の焦点が“単発の補完”から“複数の自律タスクを安全に並走させる運用”へ移っていることだ。worktreeは、そのための実務的な土台になりやすい。

worktree運用の価値は、変更を隔離しやすいことにある。Codex CLIの技術解説では、worktreeスレッドを開始すると新しいgit worktreeを作成し、そこにエージェントを実行して変更を分離する、という流れが説明されている[5][6]。同じレポジトリで複数の作業を並行させても衝突しにくく、最後に差分を見て取り込む、という設計だ。Copilot CLIのworktree対応は、この“隔離して並べる”考え方をより一般的な開発者ツールへ広げる一歩と捉えられる。

実際、Aider系のデスクトップツールのリリースノートでも、システムインストールされたCopilot CLIを正しく認識し、CLIバイナリのパス解決を改善したことや、複数モデル実行時のworktree切り替えの使い勝手向上が挙げられている[1]。これは、worktreeベースのマルチ実行がすでに一部のツールで実装上の重要テーマになっていることを示す材料だ。

つまりv1.0.78のCopilot CLIは、モデル性能そのものよりも、AIエージェントを日常の開発に組み込む際の“現場の摩擦”を減らす方向のアップデートと見るべきだろう。複数ブランチでの検証、計画と実装の分離、外部拡張の受け入れがそろっていくほど、Claude CodeやCursor、LangChain系フレームワークと比較しても、GitHub Copilotは「ターミナルの補助」から「運用可能な開発エージェント」へ近づく。今回の更新は、その基盤整備が進んだことを示している[3][2][7]。
