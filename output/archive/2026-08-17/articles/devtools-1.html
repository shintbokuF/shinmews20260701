GitHub Copilot CLIのv1.0.78でworktree対応が有効化され、エージェントCLIを複数同時に動かす際の作業分離がしやすくなった、というのが今回のポイントです。AIgent Labの検証では、同一作業ディレクトリのまま並列実行する運用の限界と、worktreeを使う意義が整理されています。[1]

GitHub Copilot CLI v1.0.78 enables worktree support, making parallel agent workflows easier to isolate. AIgent Lab’s verification highlights why running multiple agent CLIs in the same working directory is problematic and why worktrees matter.[1]

GitHub Copilot CLIのv1.0.78でworktree対応が有効化されたことで、エージェントCLIを複数同時に走らせる前提の運用が現実的になってきました。[1] これまで同じ作業ディレクトリのまま並列に動かすと、状態がぶつかったり、変更の切り分けが難しくなったりしやすく、エージェント活用のボトルネックになっていました。[1]

今回のポイントは、単に「機能が増えた」ことではありません。[1] worktreeを使うことで、ブランチごとに作業空間を分けやすくなり、複数のタスクを同時並行で進める設計に寄せやすくなる点が重要です。[1] AIエージェントの実務では、コード修正、検証、別タスクの調査を並列化したい場面が多いため、この分離は運用上のメリットが大きいといえます。[1]

一方で、worktreeは便利な反面、作業ツリー全体を複製する性質があるため、ディスク消費が増えやすいという注意点もあります。[1] ブランチも増え続けやすく、気軽に並列化すればよいわけではありません。[1] そのため、GitHub Copilot CLIのworktree対応は、AI開発ツールにおける「エージェントをどう並べるか」という設計を一歩前に進める機能であると同時に、リソース管理を含めた運用設計の重要性も改めて浮き彫りにしたと言えます。[1]
