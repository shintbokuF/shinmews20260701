AIエージェント6基盤が「Repeat-After-Me」で突破可能に──LangGraphやMicrosoft Agent Frameworkにも波及

3行でわかる！今日のニュース
  • “Repeat-After-Me”で6基盤を回避
  • LangGraphなどの信頼境界が揺らぐ
  • MCP周辺でも脆弱性研究が加速

研究者が、攻撃者が埋め込んだツール呼び出しをモデルに“復唱”させるだけで、6種類のAIエージェントフレームワークを回避できると報告しました。LangGraphやMicrosoft Agent Frameworkなど、開発者ツールの信頼境界が改めて問われています。

Researchers reported that six AI agent frameworks can be bypassed by making the model simply repeat attacker-written tool calls. The finding raises fresh concerns about the trust boundary in developer tools such as LangGraph and Microsoft Agent Framework.

AIエージェント開発では、モデルが外部ツールを呼び出す仕組みが便利さの中核ですが、今回の報告はその“つなぎ目”がいかに危ういかを示しました。研究者は、攻撃者が仕込んだツール呼び出しを、基盤モデルに「そのまま繰り返させる」だけで実行させる手口を“Repeat-After-Me”と名付け、6種類の広く使われるAIエージェントフレームワークで回避できたとしています[1]。対象にはLangGraphやMicrosoft Agent Frameworkが含まれており、開発者が普段の自然な会話や補助機能の延長として使う構成でも、意図しないツール実行が起こりうることを示唆します[1]。

重要なのは、これは単なる“プロンプトの工夫”ではなく、LLM・オーケストレーター・ツールの間にある信頼境界そのものが攻撃面になる、という点です。別の研究報告でも、MCPサーバーを含む343のAIエージェントツールを調べたところ、253件のセキュリティ脆弱性が見つかったとされ、path traversal などの問題が挙げられています[2]。つまり、エージェントの安全性はモデル単体のガードレールだけでは足りず、フレームワーク設計、ツール権限、入力の検証、そしてMCPのような接続層まで含めて再点検する必要があります[1][2]。

Claude Code、Cursor、GitHub Copilot、LangChain系の開発者ツールは、作業効率を大きく押し上げる一方で、ツール呼び出しを伴う以上、実行権限の扱いがそのままリスクになります。今回の“Repeat-After-Me”は、攻撃者が高度なゼロデイを必要としなくても、会話の流れを悪用して危険な操作を通せる可能性を示した点で重い意味を持ちます[1]。今後は、エージェントの賢さだけでなく、「何を、誰の意図で、どの権限で実行したか」を厳格に分離できる設計が、開発ツール選定の新しい評価軸になりそうです。
