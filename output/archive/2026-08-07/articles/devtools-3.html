CodeGraph OSS、Claude CodeやCursor向けの“ローカル知識グラフ”MCPサーバーとして存在感を拡大

  • CodeGraphは、コードを事前に索引化する。
  • Claude CodeやCursorへMCPで接続する。
  • ローカル完結で、探索コストを減らす。

CodeGraphは、ローカル完結でコードベースを解析し、AIエージェントが参照できる知識グラフをMCP経由で提供するOSSとして広がっている。Claude Code、Cursor、Codex CLIなどの開発者ツールに接続し、ファイルを毎回なめる代わりに、事前に索引化された構造情報を使わせるのが特徴だ。

CodeGraph is expanding as a local-first MCP server that exposes a pre-indexed code knowledge graph to AI coding agents such as Claude Code, Cursor, and Codex CLI, reducing manual file scanning and token usage.

AI開発ツールの周辺で、CodeGraphというOSSが「コードを読むAI」の補助装置として存在感を増している。GitHub上の説明では、CodeGraphはローカルファーストのコードインテリジェンスライブラリ、CLI、MCPサーバーとして設計され、tree-sitterでコードベースを解析し、SQLite（FTS5）にシンボルやエッジ、ファイル情報を保存するという [1]。要するに、AIエージェントが毎回ソースを総当たりで読むのではなく、あらかじめ整えた知識グラフを問い合わせる形だ。 [1]

この設計が刺さっている理由は、Claude CodeやCursor、Codex CLIのような開発者向けエージェントが、実装の文脈を素早く掴む必要に迫られているからだ。CodeGraphの説明には、これらのツールに対してMCP経由で知識グラフを公開するとあり、プロジェクトごとのデータはローカルの `.codegraph` 配下に置かれると読める [1]。つまり、クラウドにコードを預ける前提ではなく、手元のリポジトリをそのまま“地図化”して使う発想だ。 [1]

SNS上でも、CodeGraphは「pre-indexed code knowledge graph」や「100% local」といった言い回しで紹介されており、Claude Code、Codex、Gemini、Cursor、OpenCodeなど複数のAIコーディング環境に対応するツールとして受け止められている [3]。別の投稿では、Claude Codeがセッションごとに文脈を再構築してしまう問題に触れつつ、CodeGraphがコードベース全体の知識グラフを作ることで、より少ないトークンで理解を助けると説明されている [4]。さらに、別動画では、編集の前に「map」を与えるという表現で、symbols、routes、callers、impact pathsをクエリできる点が強調されている [5]。

この流れをまとめると、CodeGraphの価値は“AIにコードを読ませる”こと自体ではなく、“AIが迷わないように先に構造を渡す”ことにある。特に、Claude Codeのような対話型コーディング支援や、Cursorのようなエディタ統合型の体験では、検索・参照・影響範囲の把握が短時間でできるほど、修正提案の質が上がりやすい [1][5]。CodeGraphはそのためのローカルMCPレイヤーとして、AI開発ワークフローの裏方に入り込もうとしている。
