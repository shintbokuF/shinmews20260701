Anthropic、Claude Codeに“常時稼働”のProjects機能を追加し、複数AIエージェントをクラウドで並列管理可能に

3行でわかる！今日のニュース
  • Claude Code Projectsが作業を自動分岐する
  • クラウドの複数スレッドを常時並列で走らせる
  • 共有メモリで長期開発の文脈を引き継ぐ

AnthropicはClaude CodeのProjectsを再設計し、単一の会話を起点に複数のクラウドセッションへ作業を振り分ける“常時稼働”型の調整レイヤーを追加した。共有メモリや並列スレッドにより、長時間の開発タスクや複数リポジトリ横断の作業を、開発者が画面の前にいない間も進められる。[1][2][3][4]

Anthropic has redesigned Claude Code Projects into an always-on coordination layer that fans out work across multiple cloud threads. Shared memory and persistent sessions let longer-running engineering tasks continue even when the developer steps away.[1][2][3][4]

AnthropicがClaude Codeに追加したProjectsは、単なるプロジェクト管理機能ではない。VentureBeatはこれを「always on」のAI調整エージェントとして説明しており、開発者が自然言語で与えた継続タスクを細かな仕事に分解し、並列に処理する仕組みだと伝えている。[1] Startup Fortuneも、9月17日にProjectsを再投入し、エンジニアリング目標を複数のクラウドセッション（threads）に振り分けるコーディネーターが入ったと報じた。[2]

この設計のポイントは、1つの会話を起点に複数の“作業分身”を動かせることにある。MarkTechPostによれば、1つのProjectが1つの会話であり、Claudeは作業の単位ごとにthreadを立てる。各threadは独立したクラウドセッションとして、独自のブランチやリポジトリコピーを持つため、テスト実行やPR作成のような工程を同時進行しやすい。[4] Pondero Briefも、複数リポジトリにまたがる目標を渡すと、サブタスクごとにクラウドthreadを開き、移行作業、テスト、プルリク作成を同時に進めると要約している。[5]

従来のAIコーディング支援は、個別の補助や単発の提案に強い一方、長い開発の流れをまたいだ“文脈の継続”が課題だった。ZDNETは、Claude Code Projectsがマルチエージェントの混乱を抑える可能性があり、クラウド利用時はpersistent threadsとshared memoryが効く一方、ローカル開発ワークフローは新システムの対象外だと指摘している。[3] TBreakも、プロジェクト内のメモリやユーザーが用意したファイル、Claudeが生成した成果物を後続threadが再利用できるとし、数日にまたがる作業で指示や判断を引き継げる点を挙げた。[7]

一方で、この“並列化”は便利さと引き換えにコスト面の注意も伴う。The New Stackは、Projectsが工程を並列threadへ分割しつつ共有メモリを持つことで、使い方によっては利用枠を早く消費しうると報じた。[6] MarkTechPostも、parallel threadsはプラン上限をより速く消費しうると指摘している。[4] つまり、長時間・多段階の開発を任せやすくなる半面、実運用ではAIの“同時実行量”をどう制御するかが重要になる。

開発者ツール市場全体で見ると、この動きはCursorやGitHub Copilot、LangChain系のagentフレームワークが競う“AIコーディングの次の主戦場”を示している。単にコード補完を返すだけでなく、作業を分割し、状態を保ち、複数のエージェントを束ねて前に進める orchestration が差別化要因になりつつある。Claude Code Projectsは、その流れを象徴する機能として、ローカルの単独AIアシスタントからクラウド常駐の協調エージェントへと、開発体験を一段押し広げたと言える。[1][2][3][4][5][6][7][8]
