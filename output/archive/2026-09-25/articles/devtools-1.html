Plugin4ShellがAIコーディングエージェントを直撃、Claude Code・Copilot・Gemini CLIに0クリックRCEの脆弱性が浮上

3行でわかる！今日のニュース
  • SHAピニング回避で4製品にRCEが生じた。
  • Claude CodeやCopilotなどが影響を受けた。
  • 一部は修正済みだが、未対応製品も残る。

AIコーディングエージェントのプラグイン導入処理に起因する「Plugin4Shell」が公表され、Claude Code、Codex、GitHub Copilot、Gemini CLIの4製品が影響を受けた。SHAピニングの確認不備を突き、攻撃者が信頼済みコードを悪性コードへすり替えられる点が焦点だ。

Plugin4Shell exposed a zero-click RCE flaw in AI coding agents, affecting Claude Code, Codex, GitHub Copilot, and Gemini CLI. The issue stems from a SHA-pinning bypass in plugin installation that can let attackers swap trusted code for malicious code.

AIコーディングエージェントの安全性を揺るがす脆弱性「Plugin4Shell」が、開発者向けツールの利用実態を一段と重く見直させています。Air Securityが9月17日に公開したこの問題は、プラグインのインストール処理を悪用するゼロクリックのリモートコード実行で、Claude Code、OpenAI Codex、GitHub Copilot、Google Gemini CLIの4製品が影響を受けたとされています[1][2][4][5]。\n\n要点は、信頼済みコードを見極めるためのSHAピニングが、見かけ上は正しく見えても実際にはすり抜けられてしまうことです。研究者は、各エージェントが「ピン留めしたコミットをチェックアウトする」一方で、そのチェックアウト先が本当に一致しているかを確認していなかったと指摘しています。その結果、攻撃者がプラグインのGitリポジトリを握っていれば、正規コードの代わりに悪性コードへ差し替えられる余地が生まれます[1][3][6]。\n\nこの種の攻撃が厄介なのは、ユーザー操作をほぼ必要としない点です。ヘルプネットセキュリティは、4つのエージェントが「ピン留めされたコミットをチェックアウトしても、その到達先を検証していない」と説明しており、TNWもこれを「zero-click remote code execution」と表現しています[3][4]。つまり、開発者が正規のプラグインを導入したつもりでも、その裏で実行されるコードが入れ替わり得るわけです[2][5]。\n\n対応状況には差があります。CybersecurityNewsの要約では、AnthropicはClaude Code 2.1.179で修正し、OpenAIはCodex 0.146.0でパッチを当てた一方、GoogleはGemini CLIが非推奨で修正しない方針を示し、Antigravityへの移行を案内したとされています。同じくMicrosoft側のCopilotについては、公開時点で修正が出ていなかったと伝えられています[7]。また、Pasquale Pillitteriの要約では「2つだけがパッチ済み」とされており、影響製品の間で温度差があることも読み取れます[6]。\n\n今回の教訓は、AIエージェントの便利さが増すほど、外部リポジトリやプラグインの検証が“形式的に見えるだけ”では足りない、という点です。特に開発現場では、コード生成や操作代行を担うエージェントに権限を広く渡すほど、1件のサプライチェーン汚染がそのまま端末侵害へ直結します[1][3][5]。AI開発ツールの競争は機能面だけでなく、こうした導入・検証・更新の安全設計をどこまで堅牢にできるかが問われる局面に入っています。
