GitHub不調を追い風に、Cursorの独自ホスティング「Origin」が拡大　ただしデータ条項の不透明さが火種に

  • CursorがOriginを拡大しGitHub依存を揺さぶる。
  • AIエージェント向け自動化で開発体験を差別化する。
  • だがデータ条項の不透明さが新たな論点になる。

Cursorが、GitHubの継続的な不調を背景に、Paidユーザー向けの独自コードホスティング「Origin」を前面に押し出している。AIエージェント向けの自動化機能で差別化を狙う一方、コードの保管先やデータ条項が十分に公開されていない点が議論を呼んでいる。

Cursor is expanding its proprietary code hosting service, Origin, amid repeated GitHub outages. The move highlights an AI-agent-first workflow, but raises questions over where code is stored and how data terms are handled.

Cursorは、GitHubの不調が続くタイミングで、Paidユーザー向けの独自コードホスティング「Origin」を拡大した。複数メディアは、Originの公開がGitHub側の広範な障害と重なったことを指摘しており、ある報道では同日中にGitHubの機能が約20%劣化したとも伝えられている[2][8]。別の報道でも、Cursorが「GitHubの代替」としてOriginを打ち出した構図が強調された[3]。

今回の論点は、単なる“乗り換え先”の紹介にとどまらない。CursorはOriginを、AIエージェントが前提のコード保管・運用基盤として設計しており、マージコンフリクトの自動解消、失敗したCIへの対応、プルリクエスト生成などを売りにしている[6]。つまり、リポジトリを置くだけのホスティングではなく、開発作業そのものをAIに寄せるための土台として位置づけているわけだ。

一方で、懸念も残る。報道によれば、OriginはPaidユーザーでデフォルト有効とされる一方、データ条項が未公開で、コードがどこに保管され、どのような扱いを受けるのかが見えにくいとされる[4]。TechTimesは、SpaceXがPaid開発者のコードを保持することになると報じ、データ保管先への不安を示した[1]。Cursor側はOriginを“導入しやすい新基盤”として押し出しているが、実務で重要なのは機能の派手さよりも、保管場所・権限・利用条件の明確さだ。

背景には、GitHubの信頼性への継続的な不満がある。LeadDevのGitHub reliability reportを引いた複数報道では、2025年5月から2026年4月にかけて257件のGitHub障害、うち48件がmajorとされ、ほぼ週1回の大きな障害が発生していたという[1][4][5]。さらにGitHub Actionsの障害も頻発しており、AI開発の現場が“止まりやすい基盤”への代替を探し始めたことが、Cursorに追い風を与えた格好だ[4][5]。

もっとも、Originの成長は、GitHub離れの本格化を意味するというより、AI時代の開発者ツールがインフラ層まで入り込んできた象徴と見るべきだろう。Claude Code、GitHub Copilot、LangChain系のagentフレームワークが開発体験を塗り替える中で、Cursorは“AIが動きやすい保管先”まで自前で用意しようとしている[6]。ただし、その利便性を受け入れるほど、企業はコードの所在とデータ条件の透明性を厳しく問うことになる。Originは、AI開発ツールの次の競争軸が、機能だけでなく「どこに、どう預けるか」に移ったことを示している[1][4][8]。
