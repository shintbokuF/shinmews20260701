Microsoft、企業向けAIエージェントにリスクスコアと動的権限を導入　Claude CodeやCopilotなどローカルエージェントの検出対象も拡大

3行でわかる！今日のニュース
  • MicrosoftはAIエージェントの権限を動的に絞る
  • リスクスコアを継続更新して危険度を見直す
  • Claude CodeやCopilotの検出対象を60種に拡大

Microsoftは、企業内で動くAIエージェントを“常時評価”する新しいセキュリティ制御をProject Perceptionに追加した。中核は、エージェントごとにリスクスコアを更新し続ける仕組みと、タスクや期間に応じて権限を動的に絞り込む仕組みだ。あわせて、Claude Code、OpenAI Codex、GitHub Copilotを含むローカルエージェントの検出対象を60種類まで広げ、見えないエージェントまで把握しようとしている。[1][2][4][5][6][7]

Microsoft has added continuous risk scoring and dynamic permissions to Project Perception, treating enterprise AI agents as a potential insider-risk surface. It also expands local-agent discovery to 60 supported types, including Claude Code, OpenAI Codex, and GitHub Copilot.[1][2][4][5][6][7]

MicrosoftがProject Perceptionで打ち出したのは、AIエージェントを“入れたら終わり”の存在として扱わず、動いている間も監視し続ける前提の統制だ。今回の柱は、エージェントの挙動をもとにリスクスコアを継続更新する「Dynamic Agent Risk」と、タスクや継続時間に応じて権限を変える「Dynamic Permissions」で、どちらも組織やユーザーの許可範囲の中で動作を抑える方向に振っている。[1][4][5][7][8]

特に注目点は、Microsoftがローカルで動く開発者向けエージェントの発見範囲を大きく広げたことだ。対象は追加の35種類を含め合計60種類となり、Claude Code、OpenAI Codex、GitHub Copilotといった開発現場で使われるツールも含まれる。[1][2][4][5][6] つまり、クラウド上の管理されたエージェントだけでなく、各端末や開発マシンに潜む“見えにくいエージェント”まで可視化しようとしているわけだ。

この路線の背景には、MicrosoftがAIエージェントを“インサイダー脅威”に近いものとして捉えていることがある。検索結果では、Dynamic Agent RiskがID、エンドポイント、データ、クラウド、ネットワーク、実行環境、エージェント活動のシグナルを統合して評価するとされ、単発の導入時点の判定ではなく、継続的に権限の妥当性を見直す設計だと説明されている。[7] また、Entra Agent IDの拡張や、エージェント実行をサンドボックス化するMXC、さらにGuardian Agentsの追加も触れられており、Microsoftは検知、識別、隔離、監督を一体で組み合わせる方向を鮮明にしている。[5][6][8]

開発者向けに見れば、これは便利なAgentフレームワークやコーディング支援ツールの普及が、そのまま企業セキュリティの新しい管理対象になったことを意味する。Claude Code、Cursor、GitHub Copilot、LangChain系のエージェント設計が広がるほど、企業側は「誰が動かしているか」だけでなく「いま何をしてよいか」を細かく制御する必要がある。Microsoftの今回の動きは、AIエージェント活用の拡大に対し、権限を固定せず、危険度に応じて縮めるという実務的な答えを提示したものだ。[1][2][4][5][6][7]
