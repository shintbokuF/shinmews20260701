Hermes Agent v0.12.0、Azure AI FoundryとGMI Cloud対応で推論基盤を拡張

3行でわかる！今日のニュース
  • Curatorが7日周期でskill群を整備する。
  • 自己改善ループを評価重視で強化した。
  • Azure AI FoundryやGMI Cloudを追加した。

Hermes Agentのv0.12.0は、バックグラウンドでskillライブラリを定期整備するCuratorを軸に、自己改善ループを強化した。推論プロバイダーにはGMI CloudとAzure AI Foundryが加わり、LM Studioの一等対応やリモートモデル目录の自動更新も進んだ。[1][2]

Hermes Agent v0.12.0 strengthens its self-improvement loop and adds support for GMI Cloud and Azure AI Foundry as inference providers, alongside a Curator that periodically evaluates and consolidates skills.[1][2]

Hermes Agent v0.12.0は、「The Curator release」と位置づけられた更新で、単なる機能追加ではなく、エージェント自身の運用を整える方向に重心を置いた。[1][2] 中核は、gatewayのcronティッカーでデフォルト7日周期に動くバックグラウンドCuratorで、skillライブラリの評価・整理・統合を自律的に回す設計だ。[1][2]

注目点は自己改善ループの強化である。検索結果によると、ルーブリックに基づく評価、アクティブ更新への優先付け、実行環境の適切な継承、そしてmemoryとskillsのみに制限したスコープ付きtoolsetが導入された。[1][2] つまり、エージェントが何を学び、何を残し、何に触れるかをより厳密に制御しながら改善を回す仕組みが整えられたということだ。[1][2]

クラウド/AI基盤の観点では、推論プロバイダーの拡充が最もわかりやすい変化だ。GMI Cloud、Azure AI Foundry、MiniMax OAuthが新たに加わったとされ、繁体字版ではさらにTencent Tokenhubも列挙されている。[1][2][4] これにより、Hermes Agentは特定の推論先に依存しにくくなり、複数のクラウドAI基盤を前提にした運用へと広がったと読める。[1][2][4]

補足として、LM Studioが一等サポート対象になり、リモートモデル目录のmanifestは新しいバージョンを出さなくても自動更新できるようになった点も見逃せない。[2][4] これは、モデル提供元や周辺環境の変化をアプリケーション更新のたびに吸収するのではなく、運用中に追従しやすくする改善だ。[2][4]

総じてv0.12.0は、AIエージェントの能力競争を「より強いモデルを足す」だけでなく、「推論先を増やし、自己改善と保守を自動化する」方向へ押し広げたアップデートといえる。[1][2] Azure AI Foundry対応はその象徴であり、クラウド各社のAI基盤をまたいで使う実務ユースケースに寄せた動きとして注目したい。[1][2]
