Nvidia、AIエージェントの暴走を防ぐ基盤を発表　OpenShellとBlueField-4でサンドボックス化

3行でわかる！今日のニュース
  • NvidiaがAIエージェント安全基盤を発表した。
  • OpenShellとSentryで隔離監視を両立した。
  • 100社超が支持し実運用を見据えた。

Nvidiaは、AIエージェントをテスト段階から本番運用まで安全に扱うための「Open Agent Safety Platform」を発表した。ソフトウェアのOpenShellと、BlueField-4 DPU上で動く監視機構Sentryを組み合わせ、エージェントを隔離しながら動作監視する。100社超のパートナーが支持しており、開発者ツールやagentフレームワークの周辺でも注目度が高い。

Nvidia announced the Open Agent Safety Platform, a layered security framework for autonomous AI agents that combines the OpenShell sandbox runtime with the Sentry hardware watchdog on BlueField-4 DPUs. Backed by more than 100 partners, it aims to keep agents within defined boundaries from testing through deployment.

Nvidiaが9月28日に発表した「Open Agent Safety Platform」は、AIエージェントを“動かしながら縛る”ための安全基盤だ。ソフトウェア側のOpenShellでエージェントをサンドボックス化し、別系統の監視機構Sentryでふるまいを見張る二層構造を採る[4][5]。

OpenShellは、エージェントごとに隔離された実行環境を用意し、操作を追跡しながら、運用者が決めた範囲を超えないよう制御する。Nvidiaはこれをオープンソースの安全なランタイムとして位置づけ、Vera CPU向けに最適化していると説明している[5][6][8]。

一方のSentryは、BlueField-4 DPU上で動くハードウェア監視機構だ。セキュリティの判定をアプリ本体とは別のプロセッサ側に逃がすことで、エージェントが暴走したり制御を回避しようとしたりしても、別レイヤーで止めやすくする狙いがある[2][5][7]。ServeTheHomeは、この保護がBlueField-3ではなくBlueField-4向けである点を強調している[2]。

Nvidiaはこの基盤を、テストからデプロイまで一貫してエージェントの境界を守る仕組みとして打ち出した。公式発表では、業界関係者や研究者、公共部門の組織とともに安全な実装のベストプラクティスを共有し、AIエージェント導入の安全基準を引き上げることも目的に掲げている[4][6]。

今回の発表が開発者ツールの文脈で重要なのは、Claude Code、Cursor、GitHub Copilot、LangChainのようなエージェント型開発が広がるほど、「何を読めるか」「何を実行できるか」「どこで止めるか」を共通の仕組みで管理したい需要が高まるからだ。Nvidiaの提案は、その制御をアプリ側の実装任せにせず、実行基盤に寄せて標準化しようとする動きとして読める[1][4][7]。

さらに、検索結果では100社超のパートナーが支持しているとされ、単なる単体機能ではなく、周辺エコシステムを巻き込んだ“安全の参照設計”を目指していることがうかがえる[1][4]。エージェント開発が普及するほど、性能競争だけでなく、安全監視をどこまで基盤化できるかが差別化要因になりそうだ。
