Microsoft IQの4層を読み解く——Work/Web/Foundry/FabricとMCP・RAGの関係

3行でわかる！今日のニュース
  • Work・Web・Foundry・Fabricの4層で整理する
  • MCPでエージェント接続を標準化する
  • RAGで知識取得の経路を制御する

Microsoft IQは、Work・Web・Foundry・Fabricという4つの文脈レイヤーで、AIエージェントに与える情報の出どころと扱い方を整理する考え方です。MCPやRAGと組み合わせることで、開発者は「どの知識を、どこから、どう安全に引くか」を設計しやすくなります。

Microsoft IQ is a four-layer framework—Work, Web, Foundry, and Fabric—that organizes the source and handling of context for AI agents. Combined with MCP and RAG, it helps developers design where knowledge comes from and how it is safely retrieved.

Microsoft IQは、AIエージェントに与えるコンテキストを「Work」「Web」「Foundry」「Fabric」の4層で捉える見方として整理すると理解しやすい。[1][2] ざっくり言えば、社内の働き方、外部Web、企業内の知識基盤、そして業務データのライブ状態を、それぞれ別の役割として切り分ける発想だ。[2]

まずWork IQは、Microsoft 365の中で人がどう協働し、仕事がどう流れるかを表す文脈を提供する。[2] これは単なる文書検索ではなく、メール、会議、共有作業のような“仕事の進み方”をAIが理解するための土台になる。開発者ツールの観点では、エージェントが「誰が何をしているか」を把握するコンテキスト層として見ておくとわかりやすい。[2]

Web IQは、Bing groundingに代表されるように、外部Webの情報をライブに参照する層として説明できる。[3] ここで重要なのは、検索結果の抜粋にある通り、リモートソースは事前に取り込まず、取得時にライブで問い合わせる点だ。[3] つまり、外の情報を“保存して持つ”のではなく、“その場で引く”という設計に寄っている。[3]

Foundry IQは、企業の方針や手順など、制度化された知識をエージェントに渡すための層と読める。[2] 検索結果では、Foundry IQが「governed knowledge」や「curated institutional knowledge」として説明されており、単なる全文検索ではなく、統制された知識を扱う点が強調されている。[2] さらに、SharePoint 連携の例では、コンテンツがSharePointの外に出ず、権限もSharePoint側で維持されるとされている。[3] ここはRAGの実装と相性がよく、必要な文書だけを安全に引く設計として理解できる。[3]

Fabric IQは、データの“今”を扱う層だ。[2] 検索結果では、business dataのライブ状態、つまりエンティティ、メトリクス、関係、ルール、アクションを提供するとされている。[2] これはAIに「過去の知識」だけでなく、「現在の業務状態」を見せる役割を持つため、運用系のエージェントや分析系の自動化で効いてくる。[2]

この4層をMCPと並べて見ると、役割分担が見えてくる。MCPはモデルから外部ツールやサーバーへ接続するための共通化レイヤーとして使われ、Foundry側の案内では、エージェントにMCPサーバーのツールを追加する手順が示されている。[6] つまり、MCPは“どの知識層にどうつなぐか”を実装する接続口になりうる。[6]

一方RAGは、検索結果をもとに必要な知識を引いて応答に反映する仕組みだが、Microsoft IQの4層と重ねると、何を検索対象にするかを設計しやすくなる。[3] たとえば、社内文書はFoundry IQ、現在の業務データはFabric IQ、外部情報はWeb IQ、仕事の流れはWork IQというように、知識の種類ごとに取り回しを分けられる。[2][3]

開発者ツールやagentフレームワークの現場では、この整理がかなり実務的だ。Claude Code、Cursor、GitHub Copilot、LangChainのようなツールは、モデルそのものよりも「どんなコンテキストを、どの経路で、どの権限で与えるか」で体験が大きく変わる。[1][3][6] Microsoft IQの4層は、その設計図をかなり素直に言語化していると言える。[1][2]

要するに、Microsoft IQは“AIに何を覚えさせるか”ではなく、“どの情報を、どの境界で、どのタイミングで使わせるか”を整理する枠組みだ。[1][2] MCPは接続、RAGは取得、IQの4層は情報の分類と統制。これらを組み合わせることで、エージェント開発はより安全に、より説明可能に進めやすくなる。[3][6]
