AI開発ツール 2026-08-24

Slackが「Slack Code」を投入、AIエージェントと同じチャンネルで共同開発する新機能

3行でわかる！今日のニュース
  • Slack Codeで共同開発の場をSlackに移す
  • Claude Codeなどを専用チャンネルに招く
  • 計画から承認までチャットで回す

Slackは、AIエージェントを“個別のツール”ではなく、チームの会話空間に同居させる方向へ舵を切りました。新機能「Slack Code」は、Claude CodeやDevin、GitHub Copilotのようなエージェントを専用チャンネルに招き入れ、計画・コード変更・レビュー・承認までをSlack上で進められるようにするものです。開発現場のやり取りをチャットに統合することで、AI支援開発の見え方と運び方を変えようとしています。

Slack has introduced Slack Code, a collaborative coding feature that brings AI agents such as Claude Code, Devin, and GitHub Copilot into dedicated Slack channels. The workflow keeps planning, code changes, reviews, previews, and approvals inside the team chat, reframing agent-assisted development as a shared, observable process.

Slackが打ち出した「Slack Code」は、AIコード支援を“開発者の手元だけの作業”から、チーム全体が見える共同作業へ引き上げる機能だ。複数の報道は、同機能がグループチャット内にソフトウェアを作るAIエージェントを直接参加させ、チャンネル単位で開発を進められると伝えている[1][2][4]。

今回の特徴は、AIエージェントを個別の補助役ではなく、専用のプロジェクトチャンネルの一員として扱う点にある。検索結果によると、Slack CodeではチームがClaude CodeやDevin、GitHub Copilotのようなエージェントに作業を割り当て、計画を確認し、コード変更を見て、プレビューを試し、フィードバックを返し、最後は承認してデプロイまで進められる[3][8]。The Registerはこれを「multiplayer AI」と表現し、TechRepublicも、孤立した端末や開発ツールからエージェント支援開発を引き戻す狙いだと要約している[4][6]。

背景には、AI開発ツールの主戦場が“生成能力”から“協働の設計”へ移っている流れがある。Claude CodeやCursor、GitHub Copilot、LangChain系のフレームワークが注目される中で、Slackのアプローチは、コードを書く能力そのものよりも、誰がいつ何を見て、どこでレビューするかをワークスペース上に組み込む点に価値がある。WersMは、ソフトウェアがエージェントで作られる時代には、その仕事が私的な開発環境に隠れるべきではない、というSlackの考え方を指摘している[5]。

一方で、この設計は単なる利便性だけでなく、監督と責任分担の置き方も変える。専用チャンネルで作業を見せることで、エージェントの提案をそのまま受けるのではなく、チームが横で観察し、修正し、承認する流れを標準化できるからだ[3][6]。Slack自身の狙いは、AI開発を“個人の生産性向上”ではなく“チームの共同制作”として再定義することにあるように見える[1][5]。
