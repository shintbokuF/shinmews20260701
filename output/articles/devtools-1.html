Claude CodeのHTMLプレビュー脆弱性、SSH鍵やAWS認証情報まで漏えいし得る高深刻度欠陥

3行でわかる！今日のニュース
  • Claude Codeのプレビューで秘密情報が漏えいし得る。
  • SSH鍵やAWS認証情報まで奪われる恐れがある。
  • エージェントログに残りにくく検知が難しい。[1][2]

Claude Code Desktopのプレビュー表示を悪用し、開発者のSSH秘密鍵やAWS認証情報などを静かに奪える脆弱性が指摘された。エージェントの操作痕跡としては残りにくく、検知が難しい点が懸念される。[1][2]

A vulnerability in Claude Code Desktop's preview pane may let attackers silently steal developer credentials, including SSH private keys and AWS credentials. Because the malicious script runs in the preview rendering process rather than as an agent action, it may be difficult to detect in agent logs.[1][2]

AnthropicのClaude Code Desktopに関する脆弱性が、開発者向けAIツールの“便利さ”と“危険性”を同時に浮き彫りにした。報道によれば、問題はデスクトップ版のプレビュー表示領域にあり、悪意あるHTMLを見せるだけで、開発者のSSH秘密鍵やAWS認証情報、さらにはClaude関連の秘密情報まで静かに抜き取られ得るという。[1][2]

今回のポイントは、攻撃がユーザー操作を大きく要求しない「ゼロクリック」に近い形で成立しうることだ。Dark Readingはこの欠陥を“silent zero-click threat”と表現しており、ユーザーがプレビューを開いただけで被害が起こり得る構図を示している。[1] さらに Hackread は、悪意あるスクリプトはエージェントの判断ではなく、プレビュー枠のレンダリング過程で実行されると指摘している。そのため、通常のエージェントレベルのログでは不審挙動を把握しづらい。[2]

この点は、近年広がるAI開発ツール全般にとっても示唆的だ。Claude Code、Cursor、GitHub Copilot、LangChainのような開発者向けツールやエージェント基盤は、ソースコードやAPIキー、クラウド認証情報に日常的に触れる。だからこそ、UI上のプレビューや補助表示のような“脇役”に見える機能でも、実際には機密情報への入口になり得る。今回の件は、生成AIの出力そのものだけでなく、表示・レンダリング・埋め込みコンテンツの扱いまで含めて、設計上の防御を再点検すべきだと教えている。[1][2]

実務上は、AI支援ツールに与える権限の最小化、秘密情報の端末常駐を避ける運用、プレビューや外部HTMLの取り扱い分離、そしてログだけに依存しない監視が重要になる。AI開発環境は生産性を大きく押し上げる一方で、秘密情報の露出面も増やす。今回のClaude Codeの脆弱性は、そのリスクが“エージェントの暴走”ではなく、見た目には無害な表示機能からも起こりうることを示した。[1][2]
