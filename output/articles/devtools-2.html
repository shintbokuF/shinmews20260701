LangChain Blog、Deep Agentsで「コンテキストを保持しすぎない記憶」の実装法を公開

3行でわかる！今日のニュース
  • Deep Agentsで記憶設計を整理する
  • 要約とオフロードで文脈を絞り込む
  • 長期記憶を使い分けて実装する

LangChainが、長時間動くエージェント向けに「全部をコンテキストに入れない」記憶設計の考え方を公開しました。Deep Agentsのハーネスでは、オフロード、要約、skills、sub agents、長期記憶を組み合わせ、必要な情報だけを都度渡す実装がポイントです。

LangChain has published a playbook for long-running agent memory that avoids keeping everything in context. The Deep Agents harness combines offloading, summarization, skills, sub-agents, and long-term memory to pass only what is needed at each step.

LangChain Blogが示した今回のポイントは、エージェントの性能を上げるために「コンテキストを増やす」よりも、「何を入れないか」を設計する発想です。検索結果では、この投稿が「How To Remember Without Keeping Everything In Context」として紹介されており、長く動き続けるエージェントのための実践的なメモリ運用を提示していることがわかります [1][2]。

注目すべきは、Deep Agentsのハーネスがコンテキストエンジニアリングの手法を最初から備えている点です。LinkedIn上のLangChain投稿では、offloading、summarization、skills、sub agents、long-term memory が「out of the box」で使えるとされ、単一の巨大な履歴を抱え込むのではなく、役割ごとに情報を分離して扱う設計だと読み取れます [3]。

この考え方は、Snowflakeが説明するコンテキストエンジニアリングの定義とも整合的です。Snowflakeは、エージェントが各ステップで受け取るものとして、instructions、retrieved data、memory、tool definitions、prior state を挙げ、さらにそれを組み立てる広い枠組みとして harness engineering を位置づけています。つまり、記憶は「全部保存する箱」ではなく、毎回の実行に必要な情報を選別して組み立てる部品の一つだという整理です [4]。

今回のLangChainの話題が開発者ツールの文脈で重要なのは、Claude Code、Cursor、GitHub Copilotのようなコーディング支援が広がる中で、エージェントに求められるのが単発の補完ではなく、長い作業の継続支援になっているからです。検索結果にある他ソースでも、ユーザーの好みやメールの書き方のような個人記憶をManaged Deep Agentsで扱えることが示されており、実運用では「会話の全部を持つ」より「必要な記憶だけを呼び出す」設計が重視されていると考えられます [5]。

さらに、別ソースではLangChainのDeep Agentsハーネスが、会議や試験勉強のように大量の履歴が発生する場面で、最初から圧縮・分離・再利用を前提にしていることが示唆されています。120,000トークンと300トークンの対比が象徴するように、コンテキストに積み込めば積み込むほど良いわけではなく、むしろノイズを削ることがエージェントの実力を引き出す、という方向に業界の関心が移っています [6][3]。

今回の公開内容を一言でまとめるなら、Deep Agentsは「賢く覚える」のではなく「賢く忘れる」ための設計を用意した、ということです。開発者にとっては、長期タスクの中で何を要約し、何をオフロードし、何を長期記憶に残すかを明示的に設計することが、Claude CodeやCursor、GitHub Copilot時代のエージェント開発で重要な差別化要因になっていきそうです [2][3][4]。
