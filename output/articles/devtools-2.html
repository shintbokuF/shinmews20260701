CodeGraphは、Claude Code向けにコードベースをローカルの知識グラフとして扱い、探索や影響分析を効率化するMCP系ツールです。GitHub上の実装説明では、シンボル検索や呼び出し関係のたどり方、HTTPルート追跡、影響分析に対応し、Tree-sitterで10言語を自動インデックス化するとされています。[1][2] さらに関連するClaude Code Skill群でも、コード構造や依存関係をグラフ化して、複雑なリポジトリの理解を助ける位置づけが明確です。[4][5][6]

CodeGraph is a local knowledge-graph style tool for Claude Code that improves repository exploration and impact analysis. According to the GitHub and skill listings, it supports semantic search, call-graph traversal, HTTP route tracing, and auto-indexing across 10 languages via Tree-sitter.[1][2][4][5][6]

Claude Codeまわりで、リポジトリ理解を“検索”から“グラフ探索”へ寄せる流れが強まっています。その代表格がCodeGraphです。GitHub上の説明では、CodeGraphはASTベースのknowledge graph MCP serverとして位置づけられ、semantic search、call graph traversal、HTTP route tracing、impact analysisをまとめて扱えるとされています。[1] つまり、単にファイルを探すのではなく、シンボル同士の関係をたどりながら、変更の影響を見にいく設計です。[1][2]

注目したいのは、Claude Codeとの相性の良さです。GitHubの別リポジトリ説明では、Claude Codeが“Explore sub-agent”を挟まずCodeGraphツールを直接呼び出す図が示されており、エージェントの往復を減らす思想が読み取れます。[2] また、別の実装説明では、コード関連のプロンプトに対してCLI出力を小さく注入する仕組みや、Grep + Read + Globの従来手法とのベンチマークが紹介されています。[1] 検索結果の抜粋だけでも、33ファイル規模のRustプロジェクトでASTノードを使った比較を行っていることが確認でき、単なる“雰囲気の便利ツール”ではなく、探索コストを定量的に下げる方向を志向しているとわかります。[1]

MCP/Skill市場でも、CodeGraphに近い発想のツールが増えています。mcpmarketの掲載では、CodeGraphは「ローカルのグラフを構築して複雑なコードベースをナビゲートする」ためのClaude Code Skillとして説明され、別ページでも「コード依存関係をマップし、バグを追跡し、アーキテクチャを分析する」用途が打ち出されています。[4][6] さらに、Code Review Graphの掲載でも、関数・クラス・依存関係をsemantic knowledge graphへ落とし込むとされ、ローカルファーストの分析体験が共通テーマになっています。[5] これらは、LangChain系のエージェント設計やCursor/GitHub Copilotの補完体験と比べても、単発の生成より“プロジェクト全体の関係把握”を重視する潮流を示しています。[4][5][6]

では、見出しにある「ツールコール71%削減・コスト35%節約」という数字はどう見るべきでしょうか。今回の検索結果内では、その数値自体を裏づける一次情報は確認できません。[1][2] ただし、CodeGraphの構造を見ると、従来のようにGrep、Read、Globを何度も回すより、最初からグラフを使って関連箇所へ絞り込めるため、ツール呼び出しやコンテキストの無駄が減る、という主張には筋があります。[1][2] つまり重要なのは個別の数字よりも、“ローカル知識グラフで探索を先に圧縮し、LLMの往復を減らす”というアーキテクチャの方向性です。[1][2][4][5][6]

開発現場へのインパクトは大きいでしょう。巨大なコードベースでは、AIに質問しても、周辺ファイルの読み込みでトークンが膨らみやすく、答えが出るまでの試行錯誤も増えがちです。CodeGraphはそこを、シンボル・呼び出し・ルート・依存関係という“構造”で先に整理します。[1][4][6] その結果、Claude Codeのようなエージェントは、探索より判断に集中しやすくなる。ローカルで完結する知識グラフは、クラウド依存を減らしたいチームや、レガシーな大規模リポジトリを抱える組織にとって、実用的な選択肢になりそうです。[1][4][5][6]
