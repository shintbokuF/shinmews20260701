OpenAI、前線モデルのスケーリングを一時減速　一部APIにゼロデータ保持を拡大

  • OpenAIは前線学習を一時減速した。
  • 一部APIでZDR提供を広げた。
  • 安全性とデータ管理を同時に見直す。

OpenAIは、前線モデルの開発ペースを一時的に落とす一方で、対象API顧客向けにゼロデータ保持（ZDR）を拡大した。モデルの安全性・監視体制と、企業利用で重視されるデータ取り扱いの両面を同時に見直す動きとして注目される。

OpenAI is temporarily slowing frontier scaling while expanding zero data retention (ZDR) for selected API customers, signaling a parallel push on model safety and enterprise data handling.

OpenAIは2026年8月、前線モデルの開発について「一時的にスケーリングのペースを落とした」と明らかにした。報道ベースの要約によれば、対象になったのは最新モデルのRL（強化学習）訓練で、すでに完了した約2週間の停止に加え、最大規模として計画していた前線RLの実行も引き続き保留されているという[2][3]。背景には、能力の伸びが安全性や監視体制の確認速度を上回りうるという認識がある[2][4]。

この判断は、クラウドやAPIを通じてAIを提供する事業者にとっても示唆が大きい。モデル性能の競争だけでなく、どの段階で訓練や展開を止めるか、どこまで監視可能性を確保するかが、実運用の品質を左右するからだ。OpenAIの今回の動きは、単なる開発遅延ではなく、前線モデルを商用提供する際の安全設計を再調整する局面とみるべきだろう[2][4]。

同じタイミングでOpenAIは、Zero Data Retention（ZDR）の適用拡大も発表した。ZDRは、処理完了後にプロンプトや応答のコピーを保持しない構成で、対象はchat completionsやResponses系のエンドポイントを含むとされる[1]。別ソースでも、適格なAPI顧客に対して「prompts and model responses are not retained」という保証を与える仕組みとして説明されている[5]。企業ユーザーにとっては、機密情報を扱うワークロードで導入しやすくなる一方、ログ保存や監査の設計は自社側でより慎重に考える必要がある。

今回の2つの発表を合わせて見ると、OpenAIは前線モデルの供給をただ加速するのではなく、開発速度、安全性、データ保持ポリシーのバランスを取りにいっている。クラウド上でAIを使う企業にとっては、性能比較だけでなく、保持データの有無や安全審査の進め方まで含めてベンダー選定を見直す材料になる[1][2][3][4][5]。
